## Overview

GymShock is an offline-first mobile platform that delivers structured boxing training through real-time computer vision, wearable data integration, and community-driven accountability. The system analyzes posture and punching technique directly from the device camera — no additional hardware required — and generates personalized feedback to reduce injury risk and improve long-term retention.

The project targets a concrete public health problem: **26% adult obesity rate** and **70% exercise abandonment** in Colombian urban communities, where informal sports practice lacks technical structure and measurable progression.

---

## Architecture

The platform is composed of four decoupled layers, each with a clearly defined responsibility:

```
┌─────────────────────────────────────────────────────┐
│  Mobile Layer        React Native (Expo) + SQLite    │
│  Computer Vision     OpenCV + MediaPipe + PyGame     │
│  Backend API         FastAPI + PostgreSQL            │
│  Streaming Pipeline  Kafka → Spark → Azure Data Lake │
└─────────────────────────────────────────────────────┘
```

**Offline-first design**: The mobile layer operates fully without a network connection using SQLite (via Drizzle ORM) for local storage of the exercise catalog and session data. Synchronization to the backend happens asynchronously when connectivity is available.

**Vision pipeline**: Each video frame is processed by OpenCV for preprocessing (resize, normalize, color transform), then passed to MediaPipe for landmark extraction (33 body keypoints). Derived angles and distances feed a rule-based classifier that detects technique errors in real time and triggers PyGame feedback overlays.

**Async data pipeline**: Session events are published to Kafka topics, consumed by Spark Streaming for rolling averages and anomaly detection, and persisted in Azure Data Lake under a medallion architecture (bronze → silver → gold). Databricks notebooks handle exploratory analysis and model iteration.

## Key Technical Decisions

**React Native + Expo over Flutter** — TypeScript ecosystem alignment with the backend tooling, faster iteration on camera APIs, and better support for the Drizzle ORM / SQLite offline layer.

**MediaPipe over custom model** — Deployed in under a sprint with production-grade accuracy. The architecture is designed to swap it for a fine-tuned YOLO model once a labeled boxing dataset is available.

**FastAPI over Django/Express** — Async-native, automatic OpenAPI generation, and Pydantic validation aligned with the data contracts already defined in TypeScript on the mobile side.

**Kafka over direct DB writes** — Decouples the mobile client from backend processing latency. The streaming layer can evolve independently without touching the client contract.

## Features Implemented (MVP)

- **Real-time pose analysis** — MediaPipe landmark extraction at target FPS with visual feedback overlay via PyGame
- **Offline exercise catalog** — SQLite-backed, fully navigable without internet; trending exercises computed from local search history
- **Secure auth + session management** — JWT authentication with Zustand-persisted session state
- **Wearable integration (in progress)** — WearOS-first implementation; abstraction layer planned for Garmin and Apple Watch
- **Coach discovery** — Location-aware search to connect athletes with certified local coaches
- **Gamification layer** — Achievement system and progress tracking to address the retention/abandonment problem

## Challenges

**Real-time CV on mobile** — Maintaining target FPS while running MediaPipe inference on mid-range Android devices required frame-drop strategies, resolution downsampling for the analysis pipeline (separate from the preview), and careful memory management to avoid GC pressure during sessions.

**Offline-first sync** — Designing a conflict-free sync strategy between local SQLite state and the PostgreSQL backend without a dedicated sync framework. The solution uses a timestamp-based last-write-wins policy for session data and server-authoritative resolution for catalog updates.

**Human factors over technical ones** — User research showed the core problem was psychological (confidence, fear of injury, lack of visible progress) rather than technical access. This reframed the UX: the CV feedback system was redesigned to emphasize positive reinforcement and incremental correction rather than error counting.

## Outcome

The MVP validates that a single mobile device camera is sufficient for actionable boxing technique feedback — no wearables, no gym equipment, no subscription required for the core value. The modular architecture supports a pilot with the Liga de Boxeo de Belén (Medellín) and is structured for public-private partnership expansion to other cities.

**Measurable targets:** ≥30% reduction in posture errors after 4 sessions · ≥60% 3-month retention vs. 30% baseline · pilot with ≥10 athletes before scaling.
