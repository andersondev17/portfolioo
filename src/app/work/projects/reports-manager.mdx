## Overview

This project was built as a technical challenge focused on evaluating architectural decision-making, accessibility, performance optimization, and scalability in enterprise-level React applications.
The primary goal was not just feature completion, but demonstrating production-grade frontend architecture with strong separation of concerns and render optimization.

## Problem

The challenge required building a diagnostic report manager with:

- Mocked API interactions
- Real-time filtering
- Simulated file uploads with progress
- Full accessibility compliance (A11Y)
- Enterprise scalability considerations

Additionally, strict attention to referential identity and render optimization was required.

## Architectural Approach

Instead of focusing only on UI implementation, I designed the system around:

- Layered Architecture (UI → Orchestration → Domain → Infrastructure)
- Clear separation between logic and presentation
- Extensible design patterns to avoid conditionals and duplication


##Scalability Discussion (1GB+ Uploads)

The current architecture supports extension toward:

- Chunked uploads
- Direct-to-cloud uploads (S3 / Blob storage)
- Resumable uploads
- Background workers

Because upload logic is fully decoupled from UI, these improvements require minimal refactoring.

## Key Features

- **Upload Form (POST Simulation):** Multi-file drag & drop, type validation via Strategy Pattern, real-time progress, error recovery, and full ARIA accessibility.
- **Dynamic Report Management:** Server-side filtering & pagination, real-time search, sortable accessible tables, responsive cards, and helpful empty states.
- **Reusable Utilities:** `cn()` for clean Tailwind class management, `getReportColor()` for strategy-based UI mapping, `formatDate()` with `date-fns`.
- **UX & Accessibility:** Keyboard-friendly navigation, focus management, ARIA labels, modular reusable components.

## Architecture & Design

- **Layered Separation:** UI → Orchestration → Business Logic → Technical Infrastructure
- **Key Patterns:** Strategy Pattern, Facade Pattern, Column Strategy, Server Actions
- **State Management:** Zustand for efficient global state without Provider hell
- **Performance:** Server-side rendering, memoization, code splitting, and lazy loading

| Decision | Rationale | Benefit |
|--------|-----------|---------|
| Zustand over Redux | Less boilerplate, simpler mental model | Faster development, better DX |
| Server Actions | Type-safe data fetching | Reduced client JS, better SSR |
| Strategy Pattern | Avoid conditionals for file types | Easy extensibility |


## Technologies Used

- **Frontend:** Next.js 16.1, React 19.2, TypeScript, Tailwind CSS
- **State Management:** Zustand
- **Architecture:** Clean Architecture, SOLID Principles
- **Patterns:** Strategy, Facade, Column Strategy
- **Testing & Dev Tools:** Type-safe components, no `any` types in production

## Project Impact

This architecture mirrors real-world enterprise requirements such as
multi-team scalability, long-term maintainability, and strict accessibility standards.

- **Maintainable & Extensible:** Easy to add new file types or features without touching existing code
- **Performance Optimized:** SSR and memoization improve load times and responsiveness
- **Accessible:** Full keyboard and screen reader support, ARIA-compliant components
- **Scalable:** Designed to manage large datasets and files efficiently
